Thadam

Open-source testing, evaluation, and reliability tooling for AI agents.

I am building Thadam to help developers test agent behavior, investigate failures, and catch regressions before accepting changes. The core package is published on PyPI as thadam-ai; newer workflows are available from the source repository.

The evaluation problem

A plausible final answer can hide a skipped tool call or a broken workflow. Thadam lets developers specify expected behavior and inspect the evidence behind a passing or failing check.

How it works

  1. Define test cases and expectations through the Python SDK or CLI, and check outputs and tool calls.
  2. Inspect execution evidence in reports and a local dashboard. Optional LangGraph tracing connects checks to observable model and tool activity.
  3. Compare candidates against reviewed baselines to catch regressions.
  4. Repeat evaluations to measure per-case and per-check reliability.
  5. Use controlled tool failures and conversation simulations to investigate recovery and state changes across turns.

Inspect and review locally

The dashboard supports editing suites, running agents, inspecting evidence, comparing results, and reviewing baselines. Newer workflows include scenario suggestions and regression-case review, import, and fix verification.

Try the repository example

After following the checkout setup in the repository:

thadam run examples/refund_cases.json \
  --agent examples.refund_agent:run --report artifacts/report.json

python -m examples.dashboard_demo
thadam dashboard artifacts/dashboard-demo

What the evidence means

The examples use controlled local fixtures to demonstrate the runner and checks. Repeated-run pass rates are observations, rather than significance tests. Developers supply the expectations and decide which baseline changes to accept.

Package and source

Thadam is in early development. The published core package and the latest repository checkout have different feature coverage. Use the repository setup for newer dashboard, reliability, and simulation workflows, and consult its execution-boundary guidance when connecting an agent.
