Thadam

Open-source testing, evaluation, and reliability tooling for AI agents.

I’m currently working on Thadam, an early-stage open-source project for testing agent behavior and catching regressions before deployment.

The evaluation problem

A plausible final answer can hide a skipped tool call or a broken workflow. Thadam lets developers specify expected behavior and inspect the evidence behind a passing or failing check.

How the current system works

  1. Define test cases and assertions, then run a synchronous Python agent through the SDK or CLI.
  2. Inspect versioned JSON reports with outputs, errors, assertion evidence, and durations. An optional LangGraph adapter records supported model and tool callbacks.
  3. Compare candidate reports with a reviewed baseline to detect new failures and incompatible test contracts.
  4. Repeat evaluations to inspect per-case and per-check pass rates, then gate on observed reliability drops.

A useful failure case

The repository’s controlled LangGraph example includes a buggy agent that produces the same final answers but skips a required order lookup. Tool checks catch the missing behavior even when output-only checks would miss it.

Try the repository example

After following the repository’s development setup, run:

thadam run examples/refund_cases.json \
  --agent examples.refund_agent:run \
  --report artifacts/refund-report.json

What the evidence means

The examples use controlled local fixtures. They demonstrate the runner and checks, rather than establish LLM quality. Repeated-run pass rates are observations, not significance tests or proof that a code change caused a difference.

Current boundaries

Thadam runs trusted application code sequentially in the local Python process, without enforced timeouts, automatic retries, or a sandbox. Scenario generation and a dashboard remain planned. The capabilities described here belong to the project as a whole.
